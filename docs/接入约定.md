# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 client、version。raw 只领取入口文件并记录元信息；structured 按 CMake File API 回复生成目标资料，见下节。filter、region、tables、view、query、basisPath 不在支持范围，传入时不参与定位，也不做解释。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

## 结构化收件（CMake File API）

`{"mode": "structured", "client": "client-release", "version": {"major": 2}}`

- `client` 默认 `client-release`，必须是回复索引 `reply` 下的客户名称；未提供该客户、客户级 error 或版本不兼容时形成 rejected，不回退到其他客户，也不从 `objects` 列表绕过。
- 读取顺序固定为 `/build/index` → 索引当前指向的 `/build/reply/NAME` → 该客户 `query.json` 中唯一的 codemodel response 的 `jsonFile` → codemodel 内每个配置的 `targets[].jsonFile`。不扫描回复目录，不按修改时间挑选 JSON。
- 收集结束后重新读取 `/build/index` 并校验索引摘要。索引名称或内容变化时，旧回复对象可能仍在目录中：丢弃上一轮目标资料，按新索引重新收集，并在 issues 记录 `index-changed`。最多重试 3 次；仍不稳定则保留末次快照、state 为 partial，且 `coverage.complete` 为 false。
- codemodel response 不唯一时形成 `codemodel-response-ambiguous`，不做任意选择。

领域输出约定：records 每个配置内目标一条，configuration 保存配置名称，targetId 不跨配置唯一化。每条记录包含：

- `paths`：codemodel 的 source/build 基准、target 的 source/build、以及解析后的 `sourceRoot`、`buildRoot`；`target.id` 只在该配置及本次回复内定位。
- `sources`：按下标关联源码、源码组与编译组，保留 `sourceGroupIndex`、`compileGroupIndex`。每条源码给出 `sourcePath`、`buildPath`，`resolvedPath` 按 `isGenerated` 选择基准（生成文件用 build 基准）。`isGenerated` 只按 codemodel 标注，不检查磁盘是否存在。
- `sourceGroups`、`compileGroups`：保留原字段，并解析出对应源码路径；组或源码的索引越界写入 issues，不静默丢弃。
- `provenance`：索引名、客户、codemodel 与 target 文件名、回复目录、来源版本及索引/codemodel/target 的 SHA-256。

`coverage` 报告配置、目标声明/收集/缺失/失败数、源码与组计数、索引切换次数、各次尝试日志，以及 `buildCommandsExecuted: false`、`diskChecked: false`。服务只读取回复文件，不运行任何项目的构建命令。

目标文件缺失（`target-file-missing`）、声明与文件不一致（`target-id-mismatch`、`target-name-mismatch`）等可定位问题写入 issues；其余目标仍按原样输出，state 为 partial，不以残留文件拼成看似完整的构建。
