# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath。raw 只领取入口文件并记录元信息。structured 解析 CMake File API codemodel v2，必须带 `client`（对应 query.json 客户名，如 client-release）；client 缺失或非法返回 400。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

## 结构化收件流程与字段

服务不扫描 reply 目录、不按修改时间挑选 JSON，也不读取索引 `objects` 列表（其中可能残留上一代对象）。流程固定为：

1. `GET /build/index` 取得当前索引文件名并锁定本次收件的索引；
2. 读取该索引内 `reply/{client}/query.json` 的 responses，只沿本客户的 codemodel v2 响应的 `jsonFile` 取对象；客户级 error 直接形成 rejected，不能绕过；
3. 读取 codemodel，再按每个 configuration 下 target 引用的 `jsonFile` 读取目标回复；
4. 领取结束后重新询问 `/build/index`，若索引名已变化则登记 `REPLY_INDEX_DRIFTED` warning，已锁定的不可变回复仍可继续使用，但不读取新索引或目录残留对象。

领域输出约定：records 每个配置内目标一条，configuration 保存配置名称，targetId 不跨配置唯一化；同一 targetId 在不同配置下的 sources/sourceGroups/compileGroups 是互相独立的记录，不合并。每条记录含：

- `targetId`、`targetName`、`targetType`、`configuration`；
- `paths`：codemodel 级 source/build 基准与目标级基准（字符串归一化结果，不触碰磁盘）；
- `sources[]`：`stableKey`（解析后路径，重复路径附加 `#n`，不使用数组下标）、原始 `path`、`resolvedPath`、`isGenerated`、所属源码组名与编译语言；
- `sourceGroups[]`、`compileGroups[]`：保留原 `sourceIndexes`，另给 `sourceKeys` 稳定键；越界成员映射为 null 并同时登记 issue；编译组含 `fragments`；
- `evidence`：锁定的索引名、codemodel 与目标回复的 jsonFile 及 SHA-256 摘要。

issues 每条含 severity（error/warning/info）、code、中文 message、可回溯的 `location`（按回复结构的路径表达）及 detail。引用文件缺失或不可读为 `SOURCE_REFERENCE_MISSING`（partial）；生成路径登记 info 级 `GENERATED_PATH_PRESENCE_UNVERIFIED`——本服务不运行任何构建命令，不要求其当前存在。coverage 含锁定/当前索引及漂移标记、逐配置目标计数、缺失目标数、issue 计数与下载字节数；evidence.resources 列出本次每一次来源访问（角色、URL、状态、摘要），blobs 保存全部已领取原文。
